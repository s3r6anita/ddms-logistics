# Руководство ЛПР

Система сравнивает одну площадку под распределительный склад. В текущем наборе все участки, документы, спрос, маршруты и экономические параметры моковые. Результат служит учебным обоснованием; для реального решения требуются подтвержденные данные.

## Запуск

В корне проекта:

```bash
.venv312/bin/python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501 --browser.gatherUsageStats false
```

Открыть [интерфейс](http://127.0.0.1:8501). Установка с нуля описана в [README](../README.md).

## Расчеты и проверочные материалы

Старые отчеты не нужны для первого запуска. При выполнении расчета система создает новые результаты в `reports/runs/<run_id>`. Каталог не включается в Git. При отсутствии сохраненных расчетов интерфейс предлагает начать новый.

[Excel-книга AHP](../output/AHP.xlsx) является отдельным проверочным материалом и не загружается расчетным ядром. Для работы с BI сначала выполните новый расчет и передайте его в витрины.

## Сценарий решения

1. Задать бюджет **CAPEX**, множитель спроса, срок запуска, SLA и допустимый риск. Бюджет первоначальных вложений отличается от пятилетних приведенных затрат.
2. Указать шесть сравнений AHP. Число больше 1 означает приоритет первого критерия; при CR>0.10 расчет блокируется с предложением пересмотреть сравнения.
3. Оставить разрешение на моковые данные для учебного набора. Начать расчет и дождаться нового `run_id`.
4. Проверить статусы: «Исключена» — обязательное условие нарушено; «Нужно подтверждение» — критическое сведение отсутствует; «Не проходит риск» — численный сценарный фильтр не выполнен; «Расчет не завершен» — результат решателя не установлен. Только «Допущена» участвует в рекомендации.
5. Рассмотреть сумму вкладов в полезность, приведенную стоимость по статьям, совместную успешность и нижнюю границу интервала. На вкладке «Сравнение» нажать ячейку «Затраты, млн ₽»: всплывающее окно покажет первоначальные вложения, эксплуатацию, перевозки, потери спроса, ожидание запуска, вычет остаточной стоимости и итог. Все суммы — ожидаемые по проверочным сценариям, в млн ₽. Бюджет CAPEX ограничивает первоначальные вложения. Закрыть окно можно крестиком, клавишей Esc, нажатием вне окна или кнопкой «Закрыть». Статистический интервал относится к случайной выборке **внутри модели**, а не доказывает истинность экспертных распределений.
6. Открыть схему, прогноз, риски и объяснения. Схема не содержит реальной географической подложки. Интервалы прогноза недопокрывают тест; 100% проверочных успехов не равны гарантии в реальности. Стрессы закрытия дороги и задержки подключения рассмотрены отдельно от вероятностной выборки.
7. При изменении параметров выполнить новый расчет. Старый результат и его экспорт остаются неизменными. Если показан сохраненный расчет с иными параметрами, интерфейс предупреждает об этом.
8. Скачать JSON для полного аудита и HTML для чтения. Кнопка «Передать этот расчет в BI» явно переключает все BI-представления на его `run_id`; простой запуск нового расчета в форме не переключает Superset автоматически.

## Контрольные запросы

**Исходная нагрузка:** CAPEX 900 млн ₽, спрос ×1.00, α=0.90, нижняя граница Уилсона включена, SLA 90% за 120 минут, запуск ≤18 месяцев, исходные AHP-сравнения. Ожидается отсутствие рекомендации: на пятилетнем горизонте A/B не достигают принятого совместного риска, E нарушает SLA, C превышает бюджет, D не имеет подтвержденного правового статуса.

**Отдельный запрос с пониженной нагрузкой:** те же настройки, спрос ×0.75. Ожидается B, допустимая экономическая альтернатива A. Условия изменены явно; это не исправление исходных данных. Выбор не обязан совпадать с учебной агрегированной таблицей из версии 0.1 при иных весах или сценариях.

**Нехватка бюджета:** бюджет 600 млн ₽. Ожидается отсутствие рекомендации. Баллы и преимущества не отменяют бюджет.

Небольшое отличие баллов при ручном округлении сравнений нормально: AHP использует введенные значения. Точный контрольный ввод K/L=4/3, K/T=2, K/G=4, L/T=1.5, L/G=3, T/G=2 доступен в CLI-конфигурациях без округления.

## BI

После расчета в CLI выполните из корня проекта `python3 scripts/setup_superset.py`, затем `python3 scripts/run_superset.py`. Установщик сам подготавливает отдельный Python 3.11 и окружение Superset; установленный в системе `python3.11` не требуется. Первая установка требует интернета. Подробности и устранение ошибок — в [README](../README.md#superset). Проверка подключения и всех шести представлений без запуска сервера: `python3 scripts/run_superset.py --verify`.

Superset запускается отдельно на [локальном адресе](http://127.0.0.1:8089/superset/dashboard/site-dss/). Логин и пароль локального администратора находятся в `.runtime/superset/admin.json`; файл не передается в Git. На дашборде доступны сравнение, сценарии, прогноз, качество, правила и график динамики спроса. Фильтр `run_id` не должен смешивать расчеты: дополнительно все датасеты ограничены одним активным запуском. После передачи нового запуска обновить дашборд, сбросить старое значение фильтра и выбрать актуальный `run_id`. Пустой результат при фильтре старого запуска означает несовместимый фильтр, а не исчезновение сохраненного расчета.
